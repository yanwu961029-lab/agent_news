# Agent 日报 | 2026-04-29

标签：#HarnessEngineering #SessionContinuity #ClaudeCode #Cursor #OpenClaw #Hermes

## 今日判断

今天最值得关注的主线不是“又多了一个 Agent 产品”，而是三条更底层的收敛趋势正在继续增强：

1. `Harness` 正在成为 Agent 系统的主战场，尤其在 coding 和长任务场景。
2. `Context management` 正在从“喂更多信息”转向“阶段性重组、压缩和回顾”。
3. `MCP + skills + hosted/remote runtime` 正在把原本分散的 Agent 工具链拼成更完整的操作系统。

## 1. Claude Code 把“回到任务现场”的能力前置了

- 官方 changelog 显示，Claude Code 2.1.108（2026-04-14）新增了 `recap` 功能，可在离开会话后返回时自动或手动生成上下文摘要。
- 同一版本还新增了更长 TTL 的 prompt caching 开关，并让模型可以通过 Skill tool 发现和调用内置 slash commands。

我的解读：
这说明 Claude Code 已经不再只是“会在终端里写代码”，而是在认真补强 `session continuity`。对 Agent 系统而言，这很重要，因为真实工作不是单轮完成，而是经常被中断、切走、回来继续。`recap + prompt caching + skills-discoverability` 组合，指向的是更成熟的运行时体验，而不是单纯模型能力提升。

## 2. Anthropic 正式把 Harness Design 提升为一等问题

- Anthropic 在 2026-03-24 发布工程文章《Harness design for long-running application development》。
- 文章明确提出：prompt engineering 和 harness design 都曾带来明显收益，但都会碰到上限；要继续突破，需要把长任务拆解、引入结构化 artifact handoff、规划/生成/评估分工，以及更好的 context resets / compaction 策略。

我的解读：
这几乎是在给整个 Agent 行业定调。过去大家喜欢把性能提升归因到 prompt，但 Anthropic 已经非常明确地把“长任务性能”归因到 harness。对我们后续看任何 Agent 产品，都应该先看它怎么处理：状态、拆解、恢复、评估、交接，而不是先看它的 demo 有多聪明。

## 3. Cursor 的 Background Agents 已经越来越像“远程 Agent 运行平台”

- Cursor 官方文档显示，Background Agents 会在隔离的 Ubuntu 机器上异步运行，可自动编辑和执行代码。
- 支持 `.cursor/environment.json` 来定义 install/start/terminals。
- 官方还提供了 Background Agents API，可编程创建和管理后台 agent，并写明每个 API key 最多支持 256 个活跃 agents。

我的解读：
Cursor 的核心竞争力仍然是 IDE 内的 context engineering，但它正在明显向 harness 扩张。尤其是“远程隔离环境 + GitHub 分支 + 程序化 API”这一组能力，说明它的定位已经从“编辑器助手”走向“开发工作流编排器”。如果这条线继续推进，IDE、agent runtime、CI automation 的边界会越来越模糊。

## 4. OpenClaw 正在强化自己作为 MCP / skills / channel gateway 的基础设施定位

- OpenClaw 文档里，`openclaw mcp serve` 已经明确支持把 OpenClaw 作为 MCP server 暴露给 Claude Code、Codex 等 MCP clients。
- Skills 体系继续强化，官方说明 skills 可来自 bundled、managed、workspace 三层，且支持 ClawHub 安装、覆盖和按 agent workspace 隔离。
- Release Policy 也说明 OpenClaw 已形成 beta-first 的发布机制，版本命名采用 `YYYY.M.D`。

我的解读：
OpenClaw 现在最值得关注的，不是“能不能做 coding agent”，而是它在往一个 `agent connectivity layer` 演化：一边连渠道和会话，一边连 MCP 客户端，一边连 skills 生态。它更像 Agent 基础设施，而不是单一的终端产品。

## 5. Hermes 的重点在“可积累的 Agent runtime”

- Hermes 官方特性页强调 persistent memory、context files、skills system、delegation、terminal execution 等核心能力。
- GitHub Releases 显示，Hermes Agent v0.3.0（tag `v2026.3.17`）加入了 GitHub Copilot provider，并提到 400k context 支持。
- 更新文档还说明 `hermes update` 已处理依赖更新、配置迁移和 gateway auto-restart，并支持消息平台里直接 `/update`。

我的解读：
Hermes 最有辨识度的方向仍然是“会成长的 Agent”。和 Cursor、Claude Code 相比，它不是先把单次任务做得最顺，而是试图把 memory、skills、gateway、provider 兼容性整合成一个长期运行的 agent operating system。这条路线短期产品体验未必最轻，但长期很可能在“可复利能力”上更强。

## 今天最值得记住的 3 个观察

1. Agent 竞争正在从“谁回答更像人”转向“谁更像完整运行时”。
2. coding agent 已经不再只是 CLI 或 IDE 形态，而是在向 hosted runtime、background agent、MCP bridge 融合。
3. 未来半年最值得跟踪的不是单个模型分数，而是：`session continuity`、`context compaction`、`artifact handoff`、`remote runtime`、`agent evals`。

## 学习建议

- 如果今天只看一篇，优先看 Anthropic 的 Harness Design 文章，重新建立对 Agent 系统的判断框架。
- 如果想理解产品方向，今天最值得对照看的是 Claude Code changelog 和 Cursor Background Agents 文档：一个在补“继续工作”，一个在补“远程运行”。
- 如果想看开源生态，OpenClaw 和 Hermes 值得一起跟：前者看连接层，后者看长期记忆和 runtime 层。
