# Agent 日报 | 2026-04-29

标签：#HarnessEngineering #SessionContinuity #HostedRuntime #ClaudeCode

## 本日判断

今天更值得关注的不是单点产品更新，而是一个更清晰的结构性趋势：Agent 系统的竞争正在从“谁更会回答”转向“谁更像完整运行时”。如果用一句话概括，就是：2026 年真正拉开差距的，不再只是模型本身，而是 `模型 + 上下文系统 + 运行时 + 工作流` 的整体组合。

过去一段时间，Prompt Engineering 常常被当成 Agent 系统提升的核心手段，但从 Anthropic、Claude Code、Cursor、OpenClaw、Hermes 最近的更新来看，大家更真实在补的是：

- 长任务拆解
- 会话恢复
- 上下文回顾与压缩
- 远程/托管运行时
- MCP / skills / session routing

这说明 Agent 方向已经明显进入 `Harness Engineering` 阶段。

## Agent 重点进展

## 1. Claude Code：从“会编码”向“能持续工作”迈进

Claude Code 最近最重要的更新，不是再多一个 slash command，而是它开始认真补 `session continuity`。

- 官方 changelog 显示，`2.1.108`（2026-04-14）新增了 `recap`，支持在用户离开会话后自动或手动恢复上下文。
- 同一版本还加入了更长 TTL 的 prompt caching 开关。
- 模型现在可以通过 Skill tool 发现并调用内置 slash commands。
- Anthropic 在 4 月 16 日发布 `Claude Opus 4.7` 时，也同步强调了它在复杂软件工程和长任务上的提升，并在 Claude Code 里引入 `/ultrareview` 和更强的 auto mode。

我的解读：
Claude Code 现在最值得学的已经不是“终端里怎么写 prompt”，而是这一整套 coding harness 设计：

- `recap` 负责回来继续
- `prompt caching` 负责控制成本和延迟
- `ultrareview` 负责质量检查
- `auto mode` 负责减少人为阻塞

这本质上是在把“长链路 coding work”产品化。

[Claude Code changelog](https://code.claude.com/docs/en/changelog)  
[Claude Code commands](https://code.claude.com/docs/en/commands)  
[Anthropic: Claude Opus 4.7](https://www.anthropic.com/news/claude-opus-4-7)

## 2. Anthropic：明确把 Harness Design 提升为一等问题

Anthropic 3 月 24 日那篇《Harness design for long-running application development》，是今天最值得重读的一篇。

文章核心意思非常明确：

- prompt engineering 会带来收益，但会碰到上限
- harness design 也会带来收益，而且对长任务尤其关键
- 要继续突破，需要更好的任务拆解、artifact handoff、评估循环和 context reset / compaction

我的解读：
这篇文章相当于在给整个 Agent 行业定调。以后再看任何 Agent 产品，第一反应不该是“模型换了吗”，而是：

- 它怎么拆任务
- 怎么交接中间产物
- 怎么做状态管理
- 怎么处理长会话回顾
- 怎么评估 agent 的执行质量

来源：
[Anthropic: Harness design for long-running application development](https://www.anthropic.com/engineering/harness-design-long-running-apps)  
[Anthropic: Effective context engineering for AI agents](https://www.anthropic.com/engineering/effective-context-engineering-for-ai-agents)

## 3. Cursor：越来越像“云端 Agent 平台”

Cursor 官方文档最近呈现出的重点，不是继续强调 IDE 内补全，而是 Background Agents：

- 在隔离 Ubuntu 环境异步运行
- 支持 `.cursor/environment.json`
- 提供可编程 API
- 每个 API key 支持最多 `256` 个活跃 agents

这和 Latent Space 最近对 Cursor 的判断是一致的：Cursor 正在进入 “Cloud Agents” 阶段。

我的解读：
Cursor 的核心优势原本在 `Context Engineering`，但它已经在明显往 `Harness Engineering` 扩张。  
这意味着 Cursor 的竞争单位已经不只是“编辑器插件”，而是“开发工作流系统”。

## 4. OpenClaw：更像 Agent 连接层，而不是单一助手

OpenClaw 最近最值得看的点，不是单个产品功能，而是它在 MCP 和会话桥接上的定位越来越清晰。

- `openclaw mcp serve` 现在明确支持把 OpenClaw 作为 MCP server 暴露给 Claude Code、Codex 等客户端。
- 同时它也保留 MCP client-side registry 角色。
- 文档把 `openclaw mcp serve` 和 `openclaw acp` 的边界区分得很清楚：一个偏桥接 channel conversation，一个偏托管 coding harness。

我的解读：
OpenClaw 的长期价值更像：

- agent gateway
- session router
- channel bridge
- MCP exposure layer

如果说 Claude Code 是 coding harness，Cursor 是 IDE + cloud runtime，OpenClaw 更像 agent 基础设施里的连接层。

来源：
[OpenClaw MCP](https://docs.openclaw.ai/cli/mcp)  
[OpenClaw CLI](https://docs.openclaw.ai/cli)  
[OpenClaw ACP](https://docs.openclaw.ai/cli/acp)

## 5. Hermes：继续往长期运行的 Agent OS 方向演化

Hermes 最近最值得关注的不是单一功能，而是它整体往 hardening 和 runtime 成熟度方向走。

- GitHub Releases 显示 `v0.5.0 (2026-03-28)` 已进入明显的 hardening 阶段：
  - Hugging Face provider
  - 400+ models through Nous Portal
  - plugin lifecycle hooks
  - tool-use enforcement
  - 50+ security / reliability fixes
- 文档层面仍然把 persistent memory、context files、skills、delegation、terminal execution 放在核心位置。

我的解读：
Hermes 的路线不是“把一次任务做得最顺”，而是做一个：

- 可积累
- 可迁移
- 可长期运行
- 可多 provider 切换

的 agent runtime。这条路线更像 Agent OS，而不是单个产品 feature set。

来源：
[Hermes Features Overview](https://hermes-agent.nousresearch.com/docs/user-guide/features/overview/)  
[Hermes Releases](https://github.com/NousResearch/hermes-agent/releases)  
[Latent Space: AI Engineer Europe 2026](https://www.latent.space/p/ainews-ai-engineer-europe-2026)

## 今天最值得记住的 5 个结论

1. Agent 竞争单位正在从模型转向 `模型 + app + harness`。
2. `Session continuity` 正在成为成熟 Agent 产品的核心能力。
3. coding agent 正在从 IDE/CLI 形态向 hosted runtime / workflow system 继续扩张。
4. OpenClaw 与 Hermes 的价值更接近基础设施，而不是单点体验产品。
5. 2026 年更值得跟的不是“哪个 benchmark 高了 2 分”，而是运行时能力是否成熟。
