## Agent 重点进展

### 1. OpenAI 正在把 “Codex 内部能力” 外溢成通用 Agent 基础设施

- 发生了什么：OpenAI 在 2026-04-15 发布新版 Agents SDK，明确加入 configurable memory、sandbox-aware orchestration、Codex-like filesystem tools，以及对 MCP、skills、AGENTS.md、shell、apply patch 等原语的标准化支持；2026-04-27 又开源了 Symphony，把项目管理板变成 coding agents 的控制平面。来源：[OpenAI Agents SDK](https://openai.com/index/the-next-evolution-of-the-agents-sdk/) [OpenAI Symphony](https://openai.com/index/open-source-codex-orchestration-symphony/) [openai/symphony](https://github.com/openai/symphony)
- 为什么重要：这说明 OpenAI 不再只卖“更强模型”或“Codex 产品”，而是在输出一整套 agent runtime 和 orchestration 设计。尤其是 Symphony 把“一个任务对应一个 agent、持续运行、人工只做审阅”的模式公开化，等于把内部 workflow 产品化了。
- 我的解读：如果说 2025 年大家还在讨论“agent 应不应该用 framework”，那 2026 年 OpenAI 的答案更像是“少谈 framework，多谈 harness 和 control plane”。Agents SDK 负责把 agent loop 跑稳，Symphony 负责把多 agent 工作编排起来，两者一起补的是“从单 agent 到团队级 agent”的缺口。
- 值得继续追踪什么：一是 Symphony 是否会迅速出现第三方实现和 Linear/Jira 适配层；二是 OpenAI 会不会继续把 Codex CLI / App Server 的能力向 SDK 靠拢，形成统一 agent substrate。补充背景可看：[Unlocking the Codex harness](https://openai.com/index/unlocking-the-codex-harness/) [Harness engineering](https://openai.com/index/harness-engineering/)

### 2. Anthropic 在同时推进两条线：更强的 Claude Code，以及更“去产品形态”的 Managed Agents

- 发生了什么：Anthropic 2026-04-08 发布《Scaling Managed Agents: Decoupling the brain from the hands》，核心是把 session、harness、sandbox 解耦；同月 Claude Code 的 Week 16 / Week 17 更新引入了 `/ultrareview`、Routines、automatic session recaps，以及新模型 Opus 4.7 的 `xhigh` effort。来源：[Anthropic Managed Agents](https://www.anthropic.com/engineering/managed-agents) [Claude Code Week 16](https://code.claude.com/docs/en/whats-new/2026-w16) [Claude Code Week 17](https://code.claude.com/docs/en/whats-new/2026-w17) [Claude Opus 4.7](https://www.anthropic.com/news/claude-opus-4-7)
- 为什么重要：Managed Agents 代表 Anthropic 在为“长任务、托管式、企业内嵌”的 agent 服务做底层抽象；Claude Code 则代表同一家公司在把这套抽象验证到面向开发者的高频产品里。两条线互相印证，而不是彼此割裂。
- 我的解读：Anthropic 现在最领先的地方，也许不是某一条 feature，而是它对 long-running agent 的“系统工程意识”非常强。它已经不只是做一个终端工具，而是在持续证明：session durability、context transform、tool boundary、approval safety 都是第一等问题。
- 值得继续追踪什么：一是 Managed Agents 是否会进一步开放更多 hosted runtime 接口；二是 Claude Code 的 session recap、Routines、remote/cloud review 是否会被更多企业团队当成真正的“半自动 SDLC 层”。如果你关心安全面，还值得看 2026-03-25 的 auto mode 文章。来源：[Claude Code auto mode](https://www.anthropic.com/engineering/claude-code-auto-mode)

### 3. Cursor 从“AI IDE”继续往 “Agent Runtime as a Service” 走

- 发生了什么：Cursor 最近的更新非常集中地指向 agent runtime：2026-04-02 发布 Cursor 3，把 Agents Window 作为新的中心界面，支持多 agent 跨本地、worktree、cloud、SSH 并行；近期 changelog 又推出 Cursor SDK，允许开发者用同样的 runtime、harness、models 去构建 programmatic agents，并同步重构了 Cloud Agents API 为 durable agent + run-scoped streaming 模型。来源：[Cursor Changelog](https://cursor.com/changelog) [Cursor Background Agents](https://docs.cursor.com/en/background-agents)
- 为什么重要：这不是“编辑器多了一个 API”那么简单。它意味着 Cursor 正在把自己的 agent runtime 从产品功能上升为平台能力，并把 durable runs、streaming、agent lifecycle 这些云端 agent 语义公开给外部开发者。
- 我的解读：Cursor 的战略越来越清晰了：前台是一个以 agent 为中心的工作台，后台是一套云端执行与管理系统。和 OpenAI/Anthropic 的不同点在于，Cursor 仍然保留强 IDE 根性；但相同点是，它也在把“agent loop + runtime + orchestration”作为核心护城河。
- 值得继续追踪什么：一是 SDK 之后会不会迅速长出更多内建模板和生态插件；二是 cloud agents 和 self-hosted cloud agents 的取舍会不会成为 Cursor 企业化的关键分界点；三是 Composer 2、frontier models 与 Cursor runtime 的耦合程度会不会继续加深。参考判断：[Latent Space: Cursor's Third Era](https://www.latent.space/p/cursor-third-era/)

### 4. OpenClaw 正在稳固自己作为 “连接层 Agent 基础设施” 的位置

- 发生了什么：OpenClaw 官方文档现在对 `openclaw mcp` 的定位已经非常明确：既可以 `serve` 方式把 OpenClaw 作为 MCP server 暴露给 Codex、Claude Code 等客户端，也可以作为 outbound MCP registry 管理其他 server；GitHub releases 这段时间的改动则高度集中在 provider routing、plugin registry、channel routing、sandbox/browser hardening 等基础设施层面。来源：[OpenClaw MCP](https://docs.openclaw.ai/cli/mcp) [OpenClaw Docs](https://docs.openclaw.ai/index) [OpenClaw Releases](https://github.com/openclaw/openclaw/releases)
- 为什么重要：这说明 OpenClaw 的长期价值并不只是“另一个会干活的 agent”，而更像 channel gateway、session router、provider switchboard 和 MCP bridge。它和 Claude Code / Cursor 并不是同类竞品，而更像互补层。
- 我的解读：OpenClaw 最值得关注的，不是它单次任务能不能比闭源产品更聪明，而是它能不能成为不同 agent runtime 之间的通用连接器。只要 MCP 和跨渠道会话持续扩张，这个位置就有结构性价值。
- 值得继续追踪什么：一是 Anthropic / OpenAI / 本地模型 provider 的接入策略变化对 OpenClaw 的影响；二是 plugin registry 与 provider index 是否会继续演化成更像“agent app store”的层；三是安全与稳定性节奏能否跟上它快速扩张的生态。

### 5. Hermes 继续往 “长期可积累 Agent OS” 方向演化

- 发生了什么：Hermes 官方文档仍把 persistent memory、context files、skills、scheduled tasks、subagent delegation、code execution、MCP integration 放在核心特性位；GitHub 页面显示当前最新版本已到 `v0.10.0 (2026-04-16)`，并持续强化多 provider、长期记忆、并行 delegation 和跨会话能力。来源：[Hermes Features Overview](https://hermes-agent.nousresearch.com/docs/user-guide/features/overview/) [Hermes Memory](https://hermes-agent.nousresearch.com/docs/user-guide/features/memory/) [Hermes Delegation](https://hermes-agent.nousresearch.com/docs/user-guide/features/delegation) [Hermes GitHub](https://github.com/NousResearch/hermes-agent)
- 为什么重要：Hermes 的核心并不是把某一轮交互做到最丝滑，而是让 agent 具备“会积累、会复用、会长期运行”的 OS 气质。这和大量“即时完成任务”的 agent 产品形成了清晰分野。
- 我的解读：如果你关心 personal assistant / research agent / long-lived coding copilot 这些方向，Hermes 现在是少数把 memory、skills、sessions、delegation 真的放在同一设计闭环里的项目。它不一定是最轻的产品，但非常像一个值得长期观察的 runtime 分支。
- 值得继续追踪什么：一是 memory providers 和 skills hub 会不会形成网络效应；二是 ACP/IDE 集成能否把 Hermes 从“CLI/messaging agent”扩到更主流的工作入口；三是更新节奏和稳定性是否能支撑它继续扩大生态。补充来源：[Hermes Updating](https://hermes-agent.nousresearch.com/docs/getting-started/updating/)

### 6. “上下文工程” 正从经验主义快速走向显式工程学

- 发生了什么：这一周里，官方和研究两边都在强化同一件事。Anthropic 在 Managed Agents 里明确区分 durable session storage 与 harness-side context transforms；OpenAI 在 Agents SDK 中把 memory、skills、AGENTS.md、sandbox orchestration 直接当成 harness primitives；而 2026-04 的两篇 arXiv 论文则尝试把 Context Engineering 正式化为方法论。来源：[Anthropic Managed Agents](https://www.anthropic.com/engineering/managed-agents) [OpenAI Agents SDK](https://openai.com/index/the-next-evolution-of-the-agents-sdk/) [Context Engineering: A Practitioner Methodology for Structured Human-AI Collaboration](https://arxiv.org/abs/2604.04258) [Context Engineering: From Prompts to Corporate Multi-Agent Architecture](https://arxiv.org/abs/2603.09619)
- 为什么重要：这说明“Prompt Engineering”这个标签在 agent 时代已经不够用了。真正影响 agent 成败的，不只是提示词怎么写，而是上下文如何装配、什么时候压缩、哪些状态持久化、哪些东西应该作为技能延迟加载。
- 我的解读：这会直接影响未来半年所有 agent 产品的评估方式。我们会越来越少问“这个模型会不会”，越来越多问“这个系统怎样把对的上下文在对的时机交给模型”。
- 值得继续追踪什么：一是各家是否会把 context stack 更透明地产品化；二是 context engineering 会不会像 evals 一样，从经验文章发展出更稳定的工程 checklist。

## 研究 / 工程趋势小结

- 趋势 1：Harness 已经压过 framework，成为 Agent 系统的主战场。OpenAI、Anthropic、Cursor 三家都在强调 runtime、sandbox、session、tool orchestration，而不是再推一个抽象层更高的框架。来源：[OpenAI Agents SDK](https://openai.com/index/the-next-evolution-of-the-agents-sdk/) [Anthropic Managed Agents](https://www.anthropic.com/engineering/managed-agents) [Cursor Changelog](https://cursor.com/changelog)
- 趋势 2：Session durability 和 context continuity 正在成为真实生产力分水岭。自动 recap、durable runs、session log、memory snapshot 这些能力看起来像“中后台细节”，但它们决定了 agent 能否承担超过 15 分钟的工作。来源：[Claude Code Week 17](https://code.claude.com/docs/en/whats-new/2026-w17) [Hermes Memory](https://hermes-agent.nousresearch.com/docs/user-guide/features/memory/) [Cursor Background Agents](https://docs.cursor.com/en/background-agents)
- 趋势 3：Multi-agent 的价值开始从“角色扮演”转向“上下文隔离 + 并行执行 + 专业化验证”。Anthropic 在公开活动材料里已经明确提醒 multi-agent 容易被过度使用，真正稳定的适用场景是 context isolation、parallel execution、specialization。来源：[Anthropic at Google Cloud Next 2026](https://www.anthropic.com/events/anthropic-at-google-cloud-next-2026) [OpenAI Symphony](https://openai.com/index/open-source-codex-orchestration-symphony/) [Hermes Delegation](https://hermes-agent.nousresearch.com/docs/user-guide/features/delegation)
- 趋势 4：MCP、skills、AGENTS.md 正在形成跨产品的 agent compatibility layer。谁掌握这层，谁就更容易把不同入口、不同工具、不同记忆系统接成一个工作流。来源：[OpenAI Agents SDK](https://openai.com/index/the-next-evolution-of-the-agents-sdk/) [OpenClaw MCP](https://docs.openclaw.ai/cli/mcp) [Hermes Features](https://hermes-agent.nousresearch.com/docs/user-guide/features/overview/)
- 趋势 5：Hosted runtime 与 self-hosted / privacy-first runtime 的分化会越来越明显。Cursor、Anthropic、OpenAI 都在往 hosted agent 走，但 OpenClaw、Hermes 仍然代表另一条“用户掌控 runtime 与上下文”的路线，未来企业选型会越来越看重这条分界线。来源：[Cursor Background Agents](https://docs.cursor.com/en/background-agents) [Anthropic at Google Cloud Next 2026](https://www.anthropic.com/events/anthropic-at-google-cloud-next-2026) [OpenClaw Docs](https://docs.openclaw.ai/index)

## 对产品 / 业务设计的启发

- 对产品团队：真正能形成壁垒的，越来越不是“调用哪个最强模型”，而是你是否拥有自己的 session layer、memory layer、tool layer 和 evaluation loop。官方路线已经非常一致。来源：[OpenAI Agents SDK](https://openai.com/index/the-next-evolution-of-the-agents-sdk/) [Anthropic Managed Agents](https://www.anthropic.com/engineering/managed-agents)
- 对研发管理：下一阶段最值得投资的，不是更多 prompt 模板，而是更好的 repo hygiene、tests、sandbox、task decomposition 和 review automation，因为这些直接决定 agent 的上限。来源：[OpenAI Symphony](https://openai.com/index/open-source-codex-orchestration-symphony/) [Claude Code Week 16](https://code.claude.com/docs/en/whats-new/2026-w16)
- 对业务落地：如果你的目标是做“长期帮人完成工作”的 agent，今天更稳的路径通常不是先追求最全能，而是优先把 1-2 个高频工作流的 context continuity 做扎实，再逐步外接 tools、memory 和 orchestration。
